# Markdown 报告生成

把零散信息组织成**结构清晰、可复用、直接交付**的 Markdown。核心：先立提纲，再填充，一次成形。

## When to use

- 用户要"写报告 / 周报 / 总结 / 方案 / 文档 / 笔记"
- 有调研结果、对话记录、数据要落成结构化文本
- 已有 md 要补充、改写、重排

## 报告结构模板

```
# 报告标题

## 摘要
（3-5 句话，给没时间读的人）

## 背景 / 现状

## 核心结论
（要点先行，先用下表或列表给结论）

| 问题 | 结论 | 依据 |
|---|---|---|
| ... | ... | ... |

## 详细分析
### 小节 A
### 小节 B

## 下一步 / 建议
- [ ] 事项1
- [ ] 事项2

## 附录 / 参考
```

## 撰写铁律

1. **结论前置**：每节第一句给结论，证据随后。别让读者翻到底才知道重点。
2. **少废话**：删掉"众所周知""本文将从以下方面"这类填充。一句话能说明的不拆两句。
3. **表格优于列表**：对比类信息（方案/优劣势）用表格，别用长排比句。
4. **给出路**：报告结尾必须有"下一步/建议"，不然读者不知道拿它干嘛。
5. **可核查**：引用数据/来源写明出处，别编数字。

## 大纲先行

写长报告前，**先把章节骨架列出来给用户确认**（或至少在心里定好），再填内容。避免成稿后发现结构不对返工。

```markdown
# 周报骨架
## 本周完成
## 关键数据
## 问题与风险
## 下周计划
```

## 一键导出

```bash
# 转 HTML 网页分享
pandoc 报告.md -o 报告.html --standalone --metadata title="报告标题"

# 转 PDF（需 xelatex 处理中文）
pandoc 报告.md -o 报告.pdf --pdf-engine=xelatex \
  -V CJKmainfont="PingFang SC"

# 转 docx
pandoc 报告.md -o 报告.docx
```

无 pandoc 时，最轻的分享方式是页面 HTML（很多 md 编辑/预览工具直接能导出）。

## 常见坑

- 中文代码块应指定语言，否则高亮缺失（`````python`）
- 标题层级别跳级（别从 H1 直接到 H3），保持语义连续
- 表格列数不一致会渲染错乱——写前数好列
- 长文档纯 md 一段到底，读者头晕——善用 H2/H3 分节 + 摘要
- 交付时如果用户要"markdown 文件"，用文件工具把内容写到 .md 文件，不只贴对话里

## 原则

**报告的价值在结构和结论，不在篇幅。** 一份好的 md 报告 = 清晰的骨架 + 前置的结论 + 可核查的依据 + 明确的下一步。
